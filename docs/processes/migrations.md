# Database migrations

Migrations run on Alembic (async), wired to the application settings —
the URL comes from `PLOT_DATABASE_URL`, no separate Alembic
configuration. Migration files: `python/alembic/versions/`.

## Daily commands (root Makefile)

- `make db-up` — start the dev stack (PostGIS + Redis).
- `make migrate` — `alembic upgrade head`.
- `make migrate-down steps=2` — downgrade (default: one step).
- `make migration m="add listings table"` — autogenerate a revision
  from the SQLAlchemy models.

## Workflow

1. Change the models in `python/src/plot_backend/app/db/models/`.
2. `make migration m="describe the change"` (message required).
3. **Review the generated file** — autogenerate misses and overreaches;
   see the caveats below. Never ship an unreviewed migration.
4. `make migrate`, then run the tests. One migration per PR maximum.

## Autogenerate caveats (all hit for real)

- **Foreign schemas.** The env enables `include_schemas=True` with a
  name filter pinned to `public` — the postgis/postgis image ships
  built-in `tiger`/`topology` schemas that autogenerate would otherwise
  emit `DROP TABLE` for. Never widen the filter.
- **Spatial indexes.** GeoAlchemy2 `Geometry(..., spatial_index=True)`
  creates the GiST index during `create_table` itself. An autogenerated
  migration must NOT also emit an explicit `create_index` for those —
  that fails with a duplicate-index error.
- **Native enums outlive tables.** PostgreSQL enum types are not dropped
  when their table is: downgrades drop them explicitly, and the drop
  must be `DROP TYPE IF EXISTS` so a replayed or partially applied
  downgrade does not abort.
- **Stored values, not names.** Enum columns are built with
  `values_callable`, so the database stores member values (`sold`), not
  member names (`SOLD`). Data migrations must speak values.

## Conventions

- One revision per schema change, message describes the change.
- Never edit an applied migration; add a new one.
- Downgrades exist and are exercised — keep them real (the enum cleanup
  loop is the pattern to follow).
